# 内容全文审核

后台「内容审核」列表展示标题、内容摘要、学校、用户昵称、创建时间，仅提供详情入口，不提供通过、拒绝等审核按钮。列表标题和摘要均单行省略，不因长文本撑高行。鼠标悬停或键盘聚焦摘要时，通过浮层显示最多 120 个 Unicode 字符（含省略号）的正文预览。摘要合并空白，不作为审核对象，也不调用来源摘要预览接口。

进入详情后独立读取最新完整正文并保留换行，展示附件及所有审核按钮。列表不加载附件。帖子附件通过本项目认证接口读取，支持放大；附件读取或显示失败时需重试成功后才能通过，仍可拒绝内容。进入详情是审核的必要界面步骤，不以滚动位置或点击次数证明审核人员已经阅读全部信息。

默认查看待审核内容，可搜索标题/正文、切换审核状态和分页。学校由当前管理范围确定，小程序作者昵称来自本项目注册资料，后台作者显示本项目账号的显示名。审核者必须拥有本校 operator/admin 或平台管理员权限；小程序身份和普通成员不能使用管理审核接口。隐藏学校不可审核。

点击详情会独立读取当前全文、附件、版本及服务端 `review_digest`，不增加浏览量。通过审核提交当前 `revision` 和全文指纹；指纹覆盖标题、完整正文、附件、标签及版本。遇到 409 后保留审核说明，须明确重新加载并核对全文，不能自动批准修改后的新内容。

接口：

- `GET /api/v1/schools/{school}/post-reviews`：学校审核列表，JSON:API 类型为 `post-reviews`。缺省 `status=pending`；传空字符串查看全部。
- `GET /api/v1/schools/{school}/posts/{id}/review`：只读审核详情，类型为 `post-reviews`。
- `POST /api/v1/schools/{school}/posts/{id}/moderation-decisions`：沿用帖子决定路径及 `posts` 资源类型；通过时发送 `revision`、`decision=approved`、`reason`、`review_digest`。

拒绝和撤销审核只使用当前修订与说明，不依赖摘要生成或微信请求。浏览器写操作保留 Origin/CSRF 校验；服务端在事务中复查权限、学校状态及内容版本。旧 `source-preview` 审核路由、`sourcePreview` client 与 `source_preview_digest` 输入已移除，部署应同步更新 API 和 Web。

通过后的小程序来源发布继续自动生成来源摘要、准备短链接并推送，无需审核员填写或确认摘要。发布快照、帖子审核状态和 Outbox 保持同事务；微信/WeKeeper 调用仍在后台作业中完成。打开审核页面或加载审核指纹不会创建来源事件。详见 [小程序来源发布](miniapp-publication.md)。

本次没有数据库结构变更，不需要新增迁移。评论审核也以完整正文展示；其他管理列表沿用各自的业务字段。
