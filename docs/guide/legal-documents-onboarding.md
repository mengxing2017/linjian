# 协议管理与首次入驻

## 管理与公开阅读

平台管理员在 Web「系统管理 → 用户协议与隐私政策」分别维护两类文档。学校管理员、运营和小程序成员不能管理。正文为纯文本，最多 50,000 个 Unicode 标量值，空白和不可见字符不能单独作为正文。支持预览、版本化保存、单独清空、修订历史；相同正文不产生新版本。保存和清空立即生效，版本冲突不自动覆盖本地草稿。历史快照禁止更新和删除，管理操作与审计在同一事务提交。

当前列表与正文允许访客直接读取，独立于登录、学校及是否确认协议。未配置文档的正文返回 404，公开响应不包含操作人。小程序个人信息页分别展示已配置文档入口，两项均未配置时隐藏整组。阅读页按纯文本保留换行，不解释 HTML，也不要求滚到底部才能勾选。

## 同页选校与确认

入驻页包含欢迎说明、学校搜索与临时选择、已配置文档的独立默认未勾选复选框，以及「微信登录并进入」。正文链接可独立点击，不触发勾选。学校候选读取只返回名称、简称及地区；临时选校不会创建成员或绑定学校。

微信 code 只换取受限入驻票据，不发正式业务 token。首次用户必须确认当时全部已配置文档的精确版本；缺少勾选不能进入功能页。没有配置的文档不显示、不生成确认记录，但仍须选校并完成实际绑定。已完成入驻用户不因后续更新或补配重新强制勾选，仍需校验账号和学校有效性；不能用入驻入口更换已绑定学校。

服务端在事务中锁定配置及账号、校验最新文档、学校有效性和成员状态，完成学校绑定、入驻标记、正式会话与审计。任何一步失败均回滚；仅已完成实际绑定的 `ready` 响应允许小程序持久化正式 token。业务页包装器在恢复有效且已绑定的会话前不挂载业务组件；协议正文阅读页不受该守卫限制。

确认后尚未绑定时配置变动，会再次要求确认新版本；请求失败不被解释为未配置。返回阅读页保留未变化版本的临时选择与勾选。取消、票据过期及旧异步响应均不能将页面推进到业务区。

## 接口

所有请求与响应使用现有 JSON:API 契约，相关接口（含错误）均 `Cache-Control: no-store`。

| 方法与路径 | 能力 |
| --- | --- |
| `GET /api/v1/legal-documents` | 匿名读取已配置文档的类型、版本、更新时间 |
| `GET /api/v1/legal-documents/{kind}` | 匿名读取当前正文 |
| `GET/PUT /api/v1/platform/legal-documents/{kind}` | 平台浏览器会话读取/保存，写入须 Origin 与 CSRF |
| `POST /api/v1/platform/legal-documents/{kind}/clear` | 带 revision 的独立清空命令 |
| `GET /api/v1/platform/legal-documents/{kind}/revisions?page=1` | 平台读取历史，每页 20 条 |
| `GET /api/v1/onboarding/schools?query=&page=1` | 最小匿名选校目录，每页 20 条 |
| `POST /api/v1/auth/miniapp/onboarding` | 可信微信 code 换受限票据，资源类型 `onboarding` |
| `POST /api/v1/auth/miniapp/onboarding/{action}` | `status`、`confirm`、`complete`、`cancel`，同资源类型 |

`kind` 只允许 `user_agreement`、`privacy_policy`。确认命令携带 `ticket` 和 `acceptances: [{kind, revision}]`；完成命令携带 `ticket`、`school_id`、UUID `request_key`。票据接口拒绝浏览器 Origin，不接收客户端 OpenID、角色或首次状态。服务端返回 `consent_required`、`school_required`、`ready`，受限进度不包含业务 token。

票据有效 10 分钟，仅哈希落库；每个可信微信身份最多保留 10 个未过期未取消尝试。票据只存在于本页内存，不写 URL、分享、普通存储或日志。相同完成键和学校可恢复同一次结果；变更完成键或学校返回冲突。完成结果用原始票据派生的密钥进行 AES-256-GCM 认证加密，数据库不保存解密票据或明文 token；恢复窗口为完成后 2 分钟且不超过票据有效期。`status` 也允许持有同一票据者恢复结果，恢复前复查账号、会话、绑定学校有效性及成员未撤销。每分钟清理过期、取消票据及过期加密结果。票据遗失后需重新发起微信登录，不从存储恢复。

## 部署与验收

执行 forward-only migration `backend/migrations/0013_legal_documents_onboarding.sql`。按本次「无需向后兼容」指令，不提供旧 `/api/v1/auth/miniapp` 别名，不回填确认、不设 legacy 豁免；迁移撤销旧小程序会话，保留后台会话。没有本链路完成标记的账号下次登录均按首次入驻处理。API、Web、contract 和小程序须同步发布，旧版小程序须升级，不可通过回滚旧登录通道绕过确认。

自动测试涵盖公开读取、权限、正文校验、版本冲突、勾选与绑定、无配置、取消、幂等恢复和业务页守卫。数据库测试只使用明确提供的 `LINJIAN_TEST_DATABASE_URL`；`backend/examples/test_database.rs` 可启动独立临时 PostgreSQL 运行完整集成测试，不连接生产库。微信真实 code、开发者工具页面跳转与真机复选框/阅读返回交互仍需上线前人工验收。正文、确认和备份的运营留存期限尚需确定，当前不自动删除历史确认依据。
