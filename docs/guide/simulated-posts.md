# 仿真发帖

学校工作区「帖子管理 → 仿真发帖与批次」用于学校管理员和运营持续活跃论坛，发布符合校园场景、具有实际交流价值的正式帖子，不限于论坛初建。此入口要求实时有效的 `content.simulation.manage` 权限，学校管理员和运营默认拥有，平台管理员选择学校后操作；显式拒绝后不能继续操作。该权限不附赠审核权限。

## 录入与提交

界面统一使用“发布时间”，表示读者在帖子上看到的时间；填写和显示均使用北京时间。后端使用现有 Chrono 库统一生成发布时间文本，小程序和 Web 用户端直接显示，不做时间加减或时区换算。所有来源的帖子（包括用户自己发布的帖子和“我的发布”）均遵循这一规则；用户端不展示帖子创建时间和修改时间，实际时间仅供后台管理、审计和统计使用。

后台录入和筛选表单复用现有 Day.js 处理北京时间与接口时间的转换，不手工加减时间戳；这与用户端直接显示后端发布时间文本的职责分开。

每批 1～50 篇文本帖，可填写标题、正文、标签、发布时间，并为每行新建模拟作者或复用本校模拟作者。新作者昵称可填写或随机生成，头像使用从原项目迁入并压缩的 30 张校园人物头像，可选择或随机；资源独立存放于本项目，不依赖原项目运行环境。模拟作者不可登录、绑定微信或拥有后台角色，不产生注册及访问活跃事实。

点击「生成预览」后检查最终作者、头像、发布时间、逐行错误与审核模式。随机结果固定，预览有效期 30 分钟；编辑内容后必须重新预览。有错误时不能提交，提交时还会重新检查权限、学校、屏蔽词、作者及审核策略。

复用作者时，直接在每篇帖子的作者选择框输入昵称搜索，结果和翻页均在下拉框内显示。只能搜索本校已成功创建、正常启用的模拟作者，不搜索管理员或运营账号；未提交的预览作者尚未创建，不在作者池中。没有匹配结果时可选择「新建模拟作者」。

确认后整批原子提交，不产生半批帖子或孤立模拟账号。网络故障导致结果不明确时，使用原请求确认结果，不要重新创建批次；服务器通过幂等键避免重复创建。

## 审核、展示与推送

- 学校人工审核模式下，仿真发帖进入待审；自动模式产生正常的自动审核证据。仅通过且可见的帖子公开展示。
- 仿真帖子在信息流和详情按正式帖子展示，不添加初建、测试或占位内容标签。内部来源、批次、操作者和审核证据只供后台追溯，不对普通读者开放。
- 发布时间允许过去或当前，不支持未来定时发布。实际创建、审核、账号创建和审计时间始终为真实时间。
- 未手动编排的帖子默认排序权重为零，按发布时间排序，不再按递增插入权重抢占历史内容位置。显式手动排序和置顶仍优先；分页重排保留其他页顺序，新内容排在已经人工编排的内容之后。
- 仿真发帖永久仅站内，不产生来源 Outbox，也不能人工推荐推送；审核事件与必要快照正常保留。来源 Outbox 不是发送任务。
- 真实用户仍可按现有规则互动；系统不生成虚假评论、点赞、关注或浏览量。

## 批次撤销

批次页可查看帖子、实际操作者、提交时间、状态和真实互动影响。撤销须填写原因并二次确认；本批次帖子下架且不能再次公开，已删除帖子保持原状态。真实互动、模拟作者、头像、审核和审计记录保留；不影响复用作者的其他批次，也不执行物理删除。

## 统计

新增帖子按实际创建时间统计，包含仿真发帖并提供小程序投稿、后台直接发布、模拟投稿和未知来源分项。历史发布时间不会改写历史新增量。发帖及内容参与人数排除模拟账号，真实用户对仿真发帖的实际互动仍按指标口径统计。概览、趋势、学校对比和导出使用同一统计快照。

用户管理默认显示普通账号，切换「账号类型」可查看模拟作者。头像属于受控私有资产；本期不开放普通读者读取作者头像，也不扩展真实用户内置头像选择器。
