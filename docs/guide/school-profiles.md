# 学校信息与主题配置

学校管理支持名称、简称、省份、城市、区域、纬度、经度、状态、图标、头部背景图、主色、辅色、文字色。省份、城市、区域通过标准行政区划级联选择，数据随前端打包，不依赖外部接口。状态只有正常（`normal`）和隐藏（`hidden`），数据库沿用 `schools.active` 为唯一状态来源。

## 管理操作

- 平台管理员在「学校管理」创建、编辑、隐藏和恢复学校，包括隐藏学校的图片维护。新建学校只需填写基础资料，创建成功后可在提示或「学校资料」页面中上传图标和背景。
- 学校管理员默认可修改本校资料、主题及审核规则，不能修改状态；运营默认只读。实际访问以成员有效权限为准，平台可单独允许或禁止。展示资料修改与审核规则修改分别验证权限，参见[学校成员与业务权限](./member-permissions.md)。
- 列表在服务端按名称/简称/区域搜索，并按省、市、区域、状态筛选及分页；省市区筛选使用与表单相同的行政区划级联数据。更新需要当前 `revision`；冲突后保留表单输入，明确重新加载后再编辑。
- 新增学校与编辑保存后的学校经纬度必填、不能清空，使用经核实的 GCJ-02 学校代表校区坐标，最多六位小数；零值有效，不得用零坐标充当缺失数据。历史空坐标允许读取，接口返回 null，不影响启动；编辑时即使只修改其他字段，也必须补齐坐标。已有完整坐标的学校局部更新未传坐标时保留原值。颜色接受 `#RGB` 或 `#RRGGBB`，统一保存为大写六位格式。默认色为 `#6A5AF9`、`#8F6BFF`、`#FFFFFF`。

## 图片和小程序

品牌图片复用本校运营图片库，只接受本校受控资产，不接受外部 URL。上传沿用真实解码、5 MiB 及像素限制；被学校引用的图片不会作为七天未引用图片清理。

小程序选校显示简称、地区和图标，支持搜索、按省市区筛选和分页。选定学校后，首页品牌头部使用图标、背景及三色。主题文字色仅作用于学校头部。图片通过带身份的二进制请求写入 Linjian 独立临时文件，退出、账号/学校切换后清除；迟到响应不能写回旧作用域。

## 定位推荐学校

用户主动点击“推荐附近学校”并完成必要隐私与位置授权后，才读取本次位置。按约直线距离由近到远最多推荐 5 所，不足 5 所按实际数量展示，不默认选中或自动绑定。推荐之外的学校仍可手动搜索，搜索不受推荐数量、距离和定位城市限制。拒绝授权、定位或服务故障只影响推荐区；不使用 IP 或历史位置代替授权。

已有小程序会话使用 `POST /api/v1/school-recommendations`，浏览场景仅返回当前账号有访问权限的正常学校。首次入驻发生在正式会话建立之前，因此使用 `POST /api/v1/onboarding/school-recommendations`，必须携带微信登录换取的有效入驻 ticket，不要求先完成绑定，不开放无凭据的位置推荐。获取 ticket 不代表同意项目协议或绑定学校，最终仍须用户手动选校并提交原入驻确认。

两接口使用 JSON:API `school-recommendation-queries` 输入和 `school-recommendations` 集合输出。位置仅在请求内计算，不写用户资料、推荐历史、审计、Outbox、本地存储或日志；响应禁止缓存。学校选择、切账号、页面隐藏及请求超时会使旧推荐失效。换校申请保持原审核流程，不根据位置直接换校。

发布前在实际 AppID 配置定位接口能力及隐私保护指引，核对 `manifest.json` 与构建后的 `app.json` 声明，并在 iOS/Android 真机验收拒绝、撤回、系统定位关闭和超时。构建检查不能代替平台资格或真机验证；真实 AppID 不提交仓库。

正常学校的当前品牌图片可供已登录但尚未绑定学校的用户读取，不能据此访问学校内容或任意图片。接口为 `GET /api/v1/school-directory/{school}/branding/{logo|header}`；管理端图片库仍使用原学校权限。

## 隐藏与恢复

隐藏学校不出现在目录，不能新绑定或作为用户学校纠正目标，原有绑定、用户身份及成员关系保留。旧会话也不能继续访问该校社区；小程序清理学校上下文并提示联系管理员，保留登录身份。

普通资料、图片和主题变更不生成帖子来源事件，也不重建短链接。隐藏沿用既有学校失效事务及异步撤回链路，接收端故障不影响学校保存；恢复不批量重放历史内容，也不解除用户封禁。

## 迁移与接口

学校资料纳入空库基线 `backend/migrations/0001_identity_schools_settings.sql`，已部署基线后的结构变更追加 forward-only migration。API 启动沿用现有迁移机制；部署应同步更新 API、Web 和小程序。

`0016_school_coordinates_legacy_compatible.sql` 使用 NOT VALID 检查约束接替全量非空检查，保留历史空坐标（含隐藏学校），仅约束新增及更新后的行，不自动填充值。原 0014 文件和校验和不变：统一迁移入口 `database::migrate` 在迁移锁内仅对尚未执行 0014 的库跳过它，由 0016 接替；已执行库继续校验原记录并向前升级。不删除或伪造迁移历史，也不需先补齐资料才能启动。部署使用包含本修复的 API，不直接使用外部 SQLx CLI 执行原始迁移集合。若存在多校区，先确定代表点，首期不建多校区模型。

管理查询 `GET /api/v1/platform/schools`；普通目录 `GET /api/v1/school-directory`；已有学校列表、创建及学校详情/更新路径保持 `/api/v1/schools` 和 `/api/v1/schools/{school}`。目录及普通成员输出只含展示字段，不暴露学校配置或资产 ID。浏览器写操作仍校验 Origin 和 CSRF，凭据不进入图片 URL。

代码验证使用 `make check-web`、`make check-miniapp`、`devbox run -- make check-backend`，数据库测试只使用显式隔离连接或 `tools/test_database.py` 创建的临时实例。微信开发者工具及真机需另外验收图片文件展示和账号切换；研发检查不进入业务运行门禁。
