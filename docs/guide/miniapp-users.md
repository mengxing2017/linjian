# 模拟作者

仿真发帖工具创建的账号带有不可变的 `simulated` 类型，只能归属创建时的学校；它们不能认证、绑定微信、拥有登录会话或后台角色，也不产生小程序注册/活跃事实。用户管理默认显示普通账号，可通过账号类型筛选模拟作者。模拟资料、头像和帖子随批次撤销保留，不进行级联物理清理。

## 小程序用户管理与登录

小程序用户由微信 `code` 换取经后端校验的 OpenID 后自动注册；身份唯一键为 `(AppID, OpenID)`。前端不提交 OpenID、角色、学校或状态。小程序 bearer 只授予普通学校成员能力，不能访问后台管理接口；浏览器身份和小程序身份的会话、权限分别校验。

注册时无需填写昵称，后端自动生成「前缀 + 随机九位正整数」，例如「用户583194726」。默认前缀为「用户」，平台管理员可在「系统管理 → 注册昵称」修改，长度为去除首尾空白后 1～91 个 Unicode 标量值，保存仅影响之后读取到新配置的新注册用户。同一微信身份重复登录不重新命名；用户注册后可在个人资料自由修改昵称，手动昵称允许重名。

随机种子混合服务端当前时间与系统熵，数字范围为 100000000～999999999。自动生成流程在事务锁内查重完整昵称，碰撞后重新抽取，最多 32 次；配置、随机源不可用或尝试耗尽时注册失败，不降级为固定昵称。不为昵称或数字添加唯一约束或永久占号表，不要求数字跨前缀唯一，也不禁止用户之后手动改成同名。后台配置采用 revision 乐观锁，变更与审计同事务保存，接口为 `GET/PUT /api/v1/platform/miniapp-registration-settings`，仅平台浏览器会话可调用。

## 管理入口与权限

Web 的「学校管理 → 用户管理」展示头像、昵称、手机号、所属学校、发帖数、创建时间和状态。支持昵称、手机号、状态、创建时间筛选，以及创建时间、发帖数的服务端排序和分页。

学校管理员可以查看、封禁和解封本校已绑定用户，学校操作员只读。平台管理员可以切换到全部学校或未绑定用户范围，并填写原因纠正手机号、所属学校。后台账号仍在「系统管理 → 后台账号」；纯小程序用户不会出现在该列表，也不能通过该入口设置密码。

状态仅有正常和封禁。状态变更、手机号和学校纠正均使用 revision 乐观锁并记录操作审计，敏感号码在审计中脱敏。状态详情显示最近 50 条处置记录，学校管理员仅能查看本校记录。手机号筛选使用带 JSON:API 请求体的 POST 搜索接口，避免完整号码进入 URL。

封禁撤销该用户的所有小程序会话，并阻止新的小程序登录。写事务再次检查有效会话、当前学校归属及封禁状态，封禁生效后不能用旧请求身份继续写入。解封后须重新登录。封禁不改变后台账号的启用状态、浏览器会话或历史内容，不触发 Outbox。

学校纠正只改变用户当前归属和普通成员关系，不搬迁帖子、评论等历史内容；保留封禁状态，撤销小程序会话。存在相关学校管理角色冲突时拒绝纠正。发帖数统计用户在当前绑定学校中尚未删除的帖子，包括待审、驳回和隐藏内容。

## 小程序个人资料

「我的 → 个人资料」支持自行选择个人图片上传头像、昵称更新及微信授权手机号实名认证。图片无需来自仓库内置头像；上传后仅作候选预览，点击「保存头像昵称」才绑定。昵称长度为去除首尾空白后 1～100 个 Unicode 标量值，允许合法 emoji。不提供短信、密码登录或后台手动创建小程序用户。历史手填联系号码和管理员纠正号码均不自动获得微信认证状态。

### 微信手机号实名认证

访问业务内容必须登录，不提供游客模式。已登录用户无需手机号即可按原学校权限浏览；普通用户发帖、编辑提交、评论/回复和新增点赞需先完成微信授权手机号验证。撤回/删除本人内容、取消点赞、举报和私密反馈不新增手机号门槛。后台管理员、平台管理员通过有效后台会话和既有发帖权限发帖无需手机号，不能由前端角色字段触发豁免。本期不实现其他认证方式，也不改变学校准入。

首次提交或上传帖子图片前才提示核验，不在登录/浏览时弹窗。拒绝仍可浏览，正文草稿保留；本地选择但尚未上传的图片需在验证后明确重试。验证完成不自动发帖或补点赞。个人资料中可查看脱敏号码、更换号码、撤回绑定；号码不用于登录、账号合并、营销或来源 Outbox。

本人状态接口为 `GET /api/v1/miniapp/profile/phone-binding`；微信授权凭证提交到 `POST /api/v1/miniapp/profile/phone-bindings`，携带 `code`、UUID `request_id`、绑定 `revision` 和 `notice_version=linjian-phone-v1`；撤回使用 `DELETE /api/v1/miniapp/profile/phone-binding?revision=当前版本`。旧手填接口返回 `410 phone_client_upgrade_required`，后台纠正接口仅修改历史联系资料。所有接口继续使用原会话校验和 JSON:API，不接受前端提交 OpenID、AppID、号码或认证状态。

后端复用本项目 stable token 缓存，以当前会话账号映射的 OpenID 换取手机号并校验应用水印、时间和号码。仅支持国家码 86。账号锁串行化绑定、撤回和普通用户发布；微信网络请求在短事务之外执行，同一请求不会重复消费 code。微信成功但本地结果不明时先读取状态，无可信记录则重新授权，不假报成功。单账号每 30 分钟至多发起 5 次，去重请求 24 小时清理；核验/撤回审计无号码明文，保留 180 天。运营上线前应确认该留存策略及独立备份轮换策略。

部署须配置 `LINJIAN_WX_APP_ID`、`LINJIAN_WX_SECRET` 及独立的 `LINJIAN_PHONE_ENCRYPTION_KEY`（32 字节密钥的 64 位十六进制表示，例如用 `openssl rand -hex 32` 生成），密钥版本用 `LINJIAN_PHONE_ENCRYPTION_KEY_ID`，默认 v1。号码用 AES-256-GCM 加密，账号及密钥版本绑定为附加认证数据；完整号码、授权 code 和 token 不进入小程序缓存、响应或审计。密钥只在后端及独立安全备份中保存，不复用来源密钥；更换密钥时保留旧版本的受控备份，不直接丢失解密能力。未配置时新增绑定安全失败，不影响登录、合法阅读、已验证用户发布或后台发帖。

微信后台需开通对应主体的手机号能力、配置额度/告警和隐私声明，真机验证基础库、授权取消及额度不足；不得因接口异常放开未核验普通用户发布。隐私说明位于小程序「手机号隐私规则」；不存在本地手填、管理员手动标记认证或其他证件认证后门。

保存发生 revision 冲突时保留昵称与头像草稿，确认后才能重新读取并丢弃草稿。保存成功但会话刷新失败时提示「资料已保存」，仅重试显示信息刷新，不重复提交资料。网络中断导致结果不确定时先重新读取确认，不自动重放保存请求。上传、保存期间禁用资料编辑，离页、退出或切换身份后不应用过期结果。历史帖子、评论、关注列表下一次查询时显示最新昵称，不重写正文或触发来源重推。

头像保存在独立私有资产表，上传需小程序登录、限制 5 MiB 并真实解码校验图片；未绑定学校也可上传本人头像。资料只能引用本人上传的资产。头像读取需要有效会话及本人或学校/平台管理权限，不向客户端下发来源凭据。Web 使用认证请求取得 Blob；小程序使用认证请求写入独立本地文件，身份范围变化时清理。未引用且超过一天的资产由后台清理作业删除。

## 数据与上线

微信手机号核验使用独立的 forward-only migration `backend/migrations/0011_miniapp_phone_bindings.sql`，新增当前绑定与短期请求去重表；不修改旧迁移，也不把历史联系号码回填为已验证。认证 revision 与资料 revision 分开，后台纠正联系号码不会改变认证状态。

用户资料与注册昵称配置统一纳入 `backend/migrations/0004_miniapp.sql`，初始化前缀配置，并添加普通昵称查重索引。新用户昵称自动生成、头像和手机号为空、状态正常、学校未绑定。用户首次绑定学校后进入学校用户列表。当前无历史遗留数据，不执行旧昵称回填或兼容分支，使用空库初始化，不兼容整理前的迁移记录。

当前项目尚未上线，按全新用户注册设计，不回填旧用户资料、不兼容旧 OpenID 或旧会话。用户档案、注册时间和 AppID/OpenID 身份映射均在首次可信微信登录时生成。

配置后端 `LINJIAN_WX_APP_ID`、`LINJIAN_WX_SECRET`，小程序 manifest 的 AppID 需匹配；AppSecret 不进入前端环境变量。无需连接旧项目数据库或运行服务。

发布顺序：备份独立 Linjian 数据库，应用迁移及后端，发布 Web，构建并上传小程序。发布前在微信开发者工具及真机验证真实 code 登录、头像选择、昵称保存、手机号授权/拒绝/更换/撤回、学校绑定、封禁和解封重新登录。微信真实凭据与真机联调不由本地自动化测试代替。

本版本后端部署即执行发布准入，没有放行未核验用户的开关。应提前完成小程序审核与授权能力联调，协调后端部署和小程序发布窗口；切换期间旧版未核验用户需升级后授权才能发布，登录浏览仍可用。回滚展示或暂停新增绑定时仍保留后端准入，不回退 migration，也不以手填号码临时放行。

## 验证

```sh
make check-web
make check-miniapp
devbox run -- make check-backend
LINJIAN_POSTGRES_BIN=/path/to/postgresql17/bin devbox run -- python3 tools/test_database.py
```

隔离数据库回归覆盖并发注册幂等、AppID 隔离、后台账号隔离、学校权限、手机号核验与幂等重放、限流、撤回与在途请求隔离、未核验发布拦截、管理员既有权限豁免、私有头像归属、真实发帖数、状态和归属变更、会话撤销、浏览器身份保留以及用户变更不产生来源推送。数据库测试只使用显式 `LINJIAN_TEST_DATABASE_URL`，临时工具自动创建并销毁隔离实例。
