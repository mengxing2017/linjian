# 小程序换校申请与学生证明审核

## 功能范围

已绑定的真实小程序用户提交目标学校证明，平台管理员人工核验其与目标学校的学生关系；通过后原子更新归属、普通成员关系和申请结果，并撤销该用户所有小程序会话。首次绑定、浏览范围选择和后台学校管理权限保持独立。

换校不搬迁历史帖子等内容，不授予实名认证或服务提供者资格，不产生来源推送 Outbox。学校管理员、运营人员无证件访问及跨校审核权，平台管理员不能审核本人申请。

## 必要功能常开

换校申请是常开必要功能，没有受理开关；旧受理开关不再读取。只接受目标学校在读、新生，其他不接受。默认允许无学生编号的新生提交录取或入学证明，不自动恢复目标学校已撤销成员。

待审默认期限为 **3 个工作日**，超期未完成审核由系统自动驳回，仍为五状态中的 `rejected`，原因码 `review_timeout`。系统驳回不代表证明不合格，允许重新申请；不伪造人工审核人和审核时间。人工批准、驳回、撤回在截止后不能抢先覆盖系统结果。

按北京时间（UTC+08:00）从提交次日起累计工作日，截止时刻保留提交的时分秒。默认工作日为周一至周五；如需适用节假日及调休，通过 `review_holidays` 和 `review_workdays` 显式配置，系统不自动推断法定假期。例如无额外假期时周五 10:00 提交，截止为下周三 10:00。日历或期限变更只影响新申请，既有申请保留提交时算出的截止时间。

定时任务持续处理超期申请；本人结果读取、详情读取及审核/撤回也会在账号锁内处理超期。任务延迟时按原截止时间记关闭时间，材料保留期从该时间起计算，不因任务停机延长。驳回材料默认在结案后 24 小时删除。

这些是产品与发布准备事项，不是请求运行时执行的研发验收门禁。

## 配置

默认直接复用现有 `LINJIAN_MEDIA_ROOT` 存储，在其下创建权限为 0700 的 `.school-change-documents` 私有命名空间，不注册为公开媒体，不能经公开媒体接口读取。单张大小及像素限制继承现有媒体配置，最多 3 张，总大小为单张上限的 3 倍，未绑定配额 10 张。无需新增存储环境变量或策略文件。

默认未提交材料及驳回/撤回/失效材料保留 24 小时；通过材料立即拒读并自动删除。声明信息保留 30 天、审计保留 90 天，清理间隔 60 秒。默认告知正文包含这些期限。幂等摘要密钥自动随机生成并以 0600 权限保存在私有目录的 `.linjian-school-change-key`；多实例初始化互斥，重启复用，不轮换或对外下发。

`LINJIAN_SCHOOL_CHANGE_POLICY_FILE` 仍可选，用于覆盖审核、日历及保留规则，或沿用已部署的私有目录和密钥；不控制功能启停。显式配置无效时启动报错，不回退并偷偷更换材料库。使用覆盖文件时提供下列字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 告知与审核规则版本，提交必须确认当前版本 |
| `notice` | 展示给申请人的用途、访问人员、期限和权利渠道告知 |
| `review_guidance` | 平台核验目标学校、本人关系、有效性及申诉处理口径 |
| `private_root` | 独立私有存储绝对目录；允许标准私有子目录，其他路径须与公开媒体目录互不包含 |
| `digest_key` | 至少 32 字节后端密钥，仅用于幂等请求摘要，不下发前端 |
| `student_number_required` | 是否必须填写学生编号；无编号替代依据写入审核规则 |
| `restore_revoked_member` | 是否允许恢复目标校已撤销的普通成员，必须先确认限制语义 |
| `max_file_bytes` | 原图及规范化后单张上限，不超过 5 MiB |
| `max_total_bytes` | 单申请规范化材料总上限，不超过 50 MiB |
| `max_pixels` | 解码像素上限，不超过 2400 万像素 |
| `max_documents` | 每申请材料数量，1～10 |
| `max_unbound_documents` | 每人未绑定有效上传配额，最多 100 |
| `min_submission_seconds` | 提交防刷间隔，不代表固定七天业务冷却 |
| `temporary_seconds` | 未提交上传 TTL |
| `review_working_days` | 可省略，默认 3，允许 1～365；审核工作日数，超期自动驳回 |
| `review_holidays` | 可省略，默认 `[]`；非工作日期数组，格式 `YYYY-MM-DD` |
| `review_workdays` | 可省略，默认 `[]`；额外工作日数组，用于周末补班；不能与假期重叠 |
| `document_retention_seconds` | 驳回、撤回、失效后的材料保留期；通过后立即删除，不使用此期限 |
| `personal_retention_seconds` | 关闭申请后的姓名、编号、原因和结果自由文本保留期 |
| `audit_retention_seconds` | 独立换校事件保留期，不短于上述终态保留期 |
| `cleanup_interval_seconds` | 1～3600 秒，周期清理的运行间隔 |

申请保存提交时的告知版本、告知正文、审核口径及终态保留参数。保留既有策略文件、私有目录和摘要密钥，保证旧单查询、幂等重试、材料读取和清理不丢失依赖。密钥变更会使旧请求的重复提交摘要不同，不能直接替换密钥后要求旧表单无感重试。启动校验未删除材料的 store ID，防止切换默认目录后遗留原材料库。

私有目录沿用项目文件存储的安全文件操作，原图经过真实解码并重新编码为 PNG，去除无关元数据；不向公开媒体或头像资产登记。存储键由后端生成，浏览器只通过有权限的接口取得二进制流，不返回公开 URL。

部署时将私有卷及其父目录权限限制为仅后端服务账号可读写，禁止授予静态文件服务、Web 容器或其他系统用户访问；策略文件及备份采用同等隔离。应用的鉴权与目录隔离不能代替宿主机和存储卷的访问控制。

默认 Compose 使用既有媒体卷的 `/data/media/.school-change-documents`，无需新卷。原 `school-change-data` 卷仍保留挂载供既有自定义策略使用，不自动迁移或删除历史材料。可选策略文件通过只读 secret/bind mount 挂载；不要把策略密钥写入仓库或镜像。

## 用户与审核操作

- 小程序「我的」「学校」提供「换校申请与审核结果」，原学校停用或无浏览学校时仍为账号级入口。
- 用户可直接在申请页重新微信认证，查询待审或最近一次结果；批准前已有会话失效后，不用旧会话查询结果。
- 后台「学校管理」域的「换校审核」只对平台身份可见。列表不含完整个人字段，详情及每次证件读取分别审计。
- 平台用户管理详情的「查看换校申请」进入该账号的审核队列，可切换状态查看历史结果；从主导航进入则查看全平台队列。
- 审核前核对目标学校、材料中的姓名与有效学生关系。原学校证件、身份证、住址变化本身不足以通过。
- 申请必须声明 `enrolled`（在读）或 `new_student`（新生），后端拒绝其他值；声明不替代人工材料核验。历史未声明的申请不补造关系，不能批准，需撤回重提。
- 批准填写审核结论，驳回填写用户可理解的补正原因；不在结果或审计中复制无关证件号码。
- 原/目标学校存在 admin/operator 时先走学校权限管理，不静默覆盖角色。被撤销成员的恢复按显式策略检查。
- 平台纠正实际改变学校会使旧待审申请失效，包括 A→C→A；纠正到目标学校也不伪装成证件通过。
- 先成功提交的终态不可重改。发生版本冲突或网络错误后刷新核对，不自动重放批准。

## 事务与并发约定

现有学校权限更新在 fence 后锁相关账号。换校不在账号锁后获取 fence，而是复用各成员写入入口共同使用的目标账号锁；同时锁审核人与申请人时按 UUID 排序，再锁用户资料、申请及材料。不存在的成员行也受到目标账号锁保护。

所有新增成员写入口必须继续遵守该账号锁协议。小程序内容写入已有账号/资料和最新会话复核，与换校串行化；换校提交前已提交的合法内容不撤回，提交后旧会话的新写入失败。

## 清理与运行维护

- 未提交上传按 TTL 清理；绑定后切换为申请材料，不能继续按临时 TTL 删除。
- 材料仅用于本次审核。审核通过时同一事务将材料删除截止时间设为结案时间，立即禁止读取；事务提交后立即尝试物理删除，不再等待材料保留期。删除失败不撤销审核结果，由 worker 持久化重试。当前从空库初始化，不保留历史申请期限回填。
- 驳回、撤回、失效仍按材料保留期清理，到期立即不可读取，不依赖清理 worker 已经运行；声明字段到期也会在详情响应中遮蔽。审计仅留操作记录，不保留证件内容。
- worker 先标记不可访问并持久化删除意图，再删除文件；失败保留重试状态，至少五分钟后重试，多个实例通过数据库领取避免同时处理。
- 检查 `miniapp_school_change_documents` 的 `state/attempts/retry_at/deleted_at`、`miniapp_school_change_events` 和 `review_timeout` 系统驳回事件。不要在日志里输出证件、完整姓名/编号或策略密钥。
- 材料库的 `.linjian-store`、`.linjian-school-change-key` 与存储目录必须一起保存。不要把文件库替换为空目录；启动时按 store ID 检查，待核查存储恢复后再处理。
- 数据库与私有卷纳入有期限的备份。恢复后先依据逻辑删除/截止时间拒绝读取，再重跑清理，不能恢复已撤销的材料访问权。
- 既有 `forum-snapshot` 面向论坛媒体，不能视为已经自动覆盖私有材料及摘要密钥；备份与数据库保持一致，并落实备份副本的保留期限。不要把整个媒体根目录以静态文件服务公开，尤其是私有子目录。
- 已授权发送的字节或用户主动保存的副本无法远程回收；页面退出、切申请、切账号时清理临时预览，响应禁止缓存。
- 当前平台无完整账号注销流程，本期不新增注销接口；后续注销接入时必须调用换校数据清理用例，不能只删登录身份或数据库行。

## 发布与故障恢复

1. 首次在空库执行 `backend/migrations/` 分类基线；换校表与审核规则纳入 `0004_miniapp.sql`，无需旧申请回填。基线部署后的变更追加 forward-only migration。
   已有策略文件移除旧 `review_due_seconds`，改为 `review_working_days`（省略即 3），按需要提供日历数组，并更新告知版本/正文与审核口径。不要把 3 个工作日换算为固定 72 小时。
2. 完成规则确认与私有存储、备份、清理演练后，部署后端，再发布两个独立前端。
3. 换校随服务启动常开，没有额外启用步骤；平台持续安排审核人员，超期系统自动驳回。
4. 出现故障使用 forward-only 修复并恢复存储或清理，不提供关闭业务功能的开关；不能回退到不处理待审失效的旧后端，不能自动逆转已通过换校。
5. 文件存储或清理故障不影响论坛正文写入，不生成外部发送任务。

## 验证

执行 `make check-web`、`make check-miniapp`、`devbox run -- make check-backend`。数据库验收只接受显式的隔离 `LINJIAN_TEST_DATABASE_URL`，执行 `make test-integration`；也可用仓库已有 `backend/examples/test_database.rs` 启动全新临时数据库再运行该目标。

新增数据库场景接入 `backend/tests/forum_database.rs` 的 `school_changes_tests`，不得通过省略 ignored 测试宣称完成数据库验收。
