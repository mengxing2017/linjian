# 小程序用户管理与登录

小程序用户由微信 `code` 换取经后端校验的 OpenID 后自动注册；身份唯一键为 `(AppID, OpenID)`。前端不提交 OpenID、角色、学校或状态。小程序 bearer 只授予普通学校成员能力，不能访问后台管理接口；浏览器身份和小程序身份的会话、权限分别校验。

## 管理入口与权限

Web 的「学校管理 → 用户管理」展示头像、昵称、手机号、所属学校、发帖数、创建时间和状态。支持昵称、手机号、状态、创建时间筛选，以及创建时间、发帖数的服务端排序和分页。

学校管理员可以查看、封禁和解封本校已绑定用户，学校操作员只读。平台管理员可以切换到全部学校或未绑定用户范围，并填写原因纠正手机号、所属学校。后台登录账号仍在「管理功能 → 登录账号管理」；纯小程序用户不会出现在该列表，也不能通过该入口设置密码。

状态仅有正常和封禁。状态变更、手机号和学校纠正均使用 revision 乐观锁并记录操作审计，敏感号码在审计中脱敏。状态详情显示最近 50 条处置记录，学校管理员仅能查看本校记录。手机号筛选使用带 JSON:API 请求体的 POST 搜索接口，避免完整号码进入 URL。

封禁撤销该用户的所有小程序会话，并阻止新的小程序登录。写事务再次检查有效会话、当前学校归属及封禁状态，封禁生效后不能用旧请求身份继续写入。解封后须重新登录。封禁不改变后台账号的启用状态、浏览器会话或历史内容，不触发 Outbox。

学校纠正只改变用户当前归属和普通成员关系，不搬迁帖子、评论等历史内容；保留封禁状态，撤销小程序会话。存在相关学校管理角色冲突时拒绝纠正。发帖数统计用户在当前绑定学校中尚未删除的帖子，包括待审、驳回和隐藏内容。

## 小程序个人资料

「我的 → 个人资料」支持微信头像选择、昵称更新及首次手机号登记。手机号为用户自行填写，未验证归属，不能作为登录凭据；首次登记后需由平台管理员填写原因纠正。不提供短信、密码登录或后台手动创建小程序用户。

头像保存在独立私有资产表，上传需小程序登录、限制 5 MiB 并真实解码校验图片；未绑定学校也可上传本人头像。资料只能引用本人上传的资产。头像读取需要有效会话及本人或学校/平台管理权限，不向客户端下发来源凭据。Web 使用认证请求取得 Blob；小程序使用认证请求写入独立本地文件，身份范围变化时清理。未引用且超过一天的资产由后台清理作业删除。

## 数据与上线

新增 forward-only 迁移为 `backend/migrations/202611090003_miniapp_users.sql`，创建 `miniapp_users`、`miniapp_identities`、`miniapp_avatar_assets`，不重置原账号或论坛数据。新用户默认昵称「微信用户」、头像和手机号为空、状态正常、学校未绑定。用户首次绑定学校后进入学校用户列表。

当前项目尚未上线，按全新用户注册设计，不回填旧用户资料、不兼容旧 OpenID 或旧会话。用户档案、注册时间和 AppID/OpenID 身份映射均在首次可信微信登录时生成。

配置后端 `LINJIAN_WX_APP_ID`、`LINJIAN_WX_SECRET`，小程序 manifest 的 AppID 需匹配；AppSecret 不进入前端环境变量。无需连接旧项目数据库或运行服务。

发布顺序：备份独立 Linjian 数据库，应用迁移及后端，发布 Web，构建并上传小程序。发布前在微信开发者工具及真机验证真实 code 登录、头像选择、昵称保存、手机号登记、学校绑定、封禁和解封重新登录。微信真实凭据与真机联调不由本地自动化测试代替。

## 验证

```sh
make check-web
make check-miniapp
devbox run -- make check-backend
LINJIAN_POSTGRES_BIN=/path/to/postgresql17/bin devbox run -- python3 tools/test_database.py
```

隔离数据库回归覆盖并发注册幂等、AppID 隔离、后台账号隔离、学校权限、手机号首次写入、私有头像归属、真实发帖数、状态和归属变更、会话撤销、浏览器身份保留以及用户变更不产生来源推送。数据库测试只使用显式 `LINJIAN_TEST_DATABASE_URL`，临时工具自动创建并销毁隔离实例。
