# 运营中心

管理后台新增“运营中心”：群二维码、首页广告位、客户配置、投诉反馈。二维码和广告按当前学校／平台默认分别管理；学校管理员可修改本校配置，运营员只读，平台管理员可管理所有范围。客户配置仅平台管理员维护，不要求先创建学校。投诉反馈由学校管理员或平台管理员删除，运营员只读。

二维码支持每次进入、每天首次、按间隔天数展示。每天按北京时间自然日计算；按间隔天数按满 N×24 小时计算。小程序缓存键使用 Linjian 独立命名空间，按账号、学校、二维码隔离。学校有有效二维码时优先展示本校，没有则取平台默认。用户手动查看不受弹窗频率限制。

首页广告按本校优先、平台默认补充，默认五条。图片加载成功并成为当前轮播项才计曝光，每次页面展示周期每条广告最多计一次；点击按实际点击计，重试用同一事件 ID 去重，计数不会改变配置版本。管理列表、预览、预加载不计曝光。不跳转的广告仍可记录点击。统计为次数，平台广告显示跨校累计值。

客户配置控制“我的”页商务合作、申请加盟、平台客服三个入口。各入口优先使用专属二维码，缺失则使用通用兜底；都没有时提示未配置。新安装默认隐藏，普通校园服务与此配置分别维护。投诉反馈入口不受客服开关影响。

反馈提交要求选择类型、填写问题和建议及联系方式，支持最多九张本校上传图片。后台展示反馈用户、状态、IP、提交及更新时间，支持查询、详情、删除；不新增反馈编辑和状态处理。状态兼容现有“待处理／已处理／已驳回”。历史缺失类型、IP 和联系方式使用占位显示，不补造信息。原举报管理接口继续兼容历史处置；已删除反馈不能在旧入口复活。

## 升级与兼容

`202611100007_operations.sql` 为增量迁移，保留原资源、反馈及发布历史。旧二维码默认每天首次提醒，原点击量保留；曝光量从本次升级后开始累计，不能与此前无法记录的真实曝光直接比较。已有数据缺图、名称长度不合规等情况显示“待修复”，修复前不参与展示。资源和反馈采用逻辑删除，图片不会因某条记录删除而误删其他引用。

原展示资源入口只维护普通校园服务及法律文本，二维码／广告旧写接口拒绝写入并提示运营中心；原未携带事件 ID 的广告点击接口也停止累加，避免绕开幂等统计。旧客户端需更新小程序后使用新广告统计。`view=resources|platform-resources` 配合 `kind=banner|qrcode` 的链接重定向新页面；旧 `view=cases&kind=feedback&id=…` 转到投诉反馈详情。

公开展示读取仍兼容原资源接口，统一生效时间及学校边界。反馈图片由投诉专用鉴权地址读取，删除后专用地址不可再访问。新配置的媒体引用已纳入清理保护。快照导出与空库导入包含客户配置、广告事件及主表新增字段；不导入旧项目的会话或来源密钥。含新增表的快照须使用同版本工具导入。

## IP 与部署

API 从 TCP 连接取得反馈提交 IP。默认忽略 `X-Forwarded-For`。反向代理部署可设置 `LINJIAN_TRUSTED_PROXY_IPS`，逗号分隔填写真正受控的代理 IP；从连接端向左逐跳剥离可信代理，在第一个不可信地址处停止。不要把用户地址或不受控网段设为可信代理。Compose 已转交该变量；为空时保存代理连接地址，历史反馈未记录的 IP 保持空值。

发布前备份独立 Linjian 数据库；先上线增量迁移及 API，再更新 Web 和小程序。回退应用需使用兼容新增字段的版本，不修改既有 migration，不执行反向迁移。配置、反馈与曝光点击不产生来源 Outbox，不引入群发、设备或发送授权。

## 验证

执行 `make check-web`、`devbox run -- make check-backend`、`make check-miniapp`。数据库测试只读取 `LINJIAN_TEST_DATABASE_URL`；也可通过 `devbox run -- python3 tools/test_database.py --bin-dir <PostgreSQL bin>` 启动仅监听临时 Unix socket 的数据库并运行 `make test-integration`。这些是研发检查，不构成业务运行门禁。小程序最终交互仍需在微信开发者工具及真机验证。
