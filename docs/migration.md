# 论坛数据迁移操作

工具仅对显式连接操作：导出读取 `LINJIAN_MIGRATION_SOURCE_URL`，导入读取 `LINJIAN_MIGRATION_TARGET_URL`，无应用或生产地址回退。先在隔离备份副本完成演练。此说明不是已执行的生产操作。

## 导出

```sh
cargo run --locked --manifest-path backend/Cargo.toml --bin forum-snapshot -- export /secure/path/forum-snapshot.json
```

导出使用 REPEATABLE READ READ ONLY 事务获取一致快照；只读取论坛表白名单。包含学校、设置、全部登录账号与密码哈希、成员和角色、社区和审核、展示资源、媒体字节、关联历史标识和论坛审计。账号管理中企业成员映射所需目录身份可迁入，核验状态重置为 unverified，须在论坛自己的配置下重新核验。

源连接使用专用只读数据库角色；文件以 create_new 和 0600 创建，不覆盖已有文件。工具只输出摘要和数量，不打印数据库地址、密码、正文或快照数据。

## 导入与核对

```sh
cargo run --locked --manifest-path backend/Cargo.toml --bin forum-snapshot -- import /secure/path/forum-snapshot.json
# 含 wx_openid 时，仅在继续使用同一微信小程序 AppID 的情况下加 --same-wechat-app
```

目标应为全新的独立数据库。工具拒绝迁移已有的非 Linjian 数据库；建立论坛独立基线后，拒绝覆盖已有论坛业务数据。导入在单事务中执行，显式处理外键次序与生成列，导入后按表比较原始内容及媒体字节；任一差异回滚。成功记录源摘要、目标摘要、每表数量和迁移批次。

学校、用户、内容等 UUID 保持不变。会话、OAuth state、平台缓存、旧来源密钥、目标群、手机和发送事实不导入；原发送账本继续留在原项目。历史帖子不生成事件，初始来源版本由其 revision 建立，后续编辑和撤回继续递增；不会自动重发历史内容。

若 AppID 改变，openid 也改变，不能使用 `--same-wechat-app`。须先提供可核对的身份映射和新绑定流程；工具会拒绝直接导入此类快照，避免生成无法登录或串号的账号。密码哈希沿用现有 Argon2 验证实现；抽样验证失败时使用论坛平台管理员重设密码，旧会话始终失效。

导入工具目前按完整快照加载数据；大媒体库需预估内存及维护窗口，不能未经演练直接执行。快照只包含原项目数据库保存的媒体字节，不抓取外部链接，也不复制未被数据库引用的历史上传目录。

## 最终交接与回退

1. 迁移清单、独立构建和演练核对通过前，不改动 wekeeper。
2. 约定最终窗口，使用现有运维能力暂停旧论坛所有写入口，保持转发链路运行。若现有能力不足，先落实外部流量隔离，不能提前改造原代码。
3. 重新导出最终快照，导入新的目标库，核对数量、正文、媒体、审核可见性、学校成员权限、登录与账号管理。
4. 切换 Web、管理后台、小程序地址与合法域名，确认 linjian 成为唯一论坛写入方。Outbox 可先持久积压；接收端联调不阻塞论坛运行。
5. 论坛迁移完成后，才单独推进 wekeeper 来源接入、来源切换及旧实现清理。此仓库不执行这些改造。

切换前可撤回新入口。新论坛产生写入后，停止写入并核对全部新增变更后才能考虑回退，否则优先前向修复。不得恢复旧快照覆盖发送事实，不得重放历史成功任务，不执行 down migration。原项目的其他现有工作不得覆盖或回退。

导入成功后记录 source_import_batches 与 source_imported_posts，delivery_intent 固定为 false。导入历史不建立来源路由投影，不因学校重新启用或配置路由自动补投；真实正文编辑后才开始该内容的实时来源版本。
