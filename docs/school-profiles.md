# 学校信息与主题配置

学校管理支持名称、简称、省份、城市、区域、纬度、经度、状态、图标、头部背景图、主色、辅色、文字色。状态只有正常（`normal`）和隐藏（`hidden`），数据库沿用 `schools.active` 为唯一状态来源。

## 管理操作

- 平台管理员在「学校管理」创建、编辑、隐藏和恢复学校，包括隐藏学校的图片维护。新建学校先保存，再进入编辑上传图标和背景。
- 学校管理员通过本校「学校设置」修改资料、主题及审核规则，不能修改状态；操作员只能读取本校正常学校资料。
- 列表在服务端按名称/简称/区域搜索，并按省、市、区域、状态筛选及分页。更新需要当前 `revision`；冲突后保留表单输入，明确重新加载后再编辑。
- 经纬度必须同时填写或同时清空，最多六位小数；零值有效。颜色接受 `#RGB` 或 `#RRGGBB`，统一保存为大写六位格式。默认色为 `#6A5AF9`、`#8F6BFF`、`#FFFFFF`。

## 图片和小程序

品牌图片复用本校运营图片库，只接受本校受控资产，不接受外部 URL。上传沿用真实解码、5 MiB 及像素限制；被学校引用的图片不会作为七天未引用图片清理。

小程序选校显示简称、地区和图标，支持搜索和分页。选定学校后，首页品牌头部使用图标、背景及三色。主题文字色仅作用于学校头部。图片通过带身份的二进制请求写入 Linjian 独立临时文件，退出、账号/学校切换后清除；迟到响应不能写回旧作用域。

正常学校的当前品牌图片可供已登录但尚未绑定学校的用户读取，不能据此访问学校内容或任意图片。接口为 `GET /api/v1/school-directory/{school}/branding/{logo|header}`；管理端图片库仍使用原学校权限。

## 隐藏与恢复

隐藏学校不出现在目录，不能新绑定或作为用户学校纠正目标，原有绑定、用户身份及成员关系保留。旧会话也不能继续访问该校社区；小程序清理学校上下文并提示联系管理员，保留登录身份。

普通资料、图片和主题变更不生成帖子来源事件，也不重建短链接。隐藏沿用既有学校失效事务及异步撤回链路，接收端故障不影响学校保存；恢复不批量重放历史内容，也不解除用户封禁。

## 迁移与接口

新增 forward-only 迁移 `backend/migrations/202611090004_school_profiles.sql`，不改旧基线。API 启动沿用现有迁移机制；部署应同步更新 API、Web 和小程序，不需要旧学校数据或旧主题兼容配置。

管理查询 `GET /api/v1/platform/schools`；普通目录 `GET /api/v1/school-directory`；已有学校列表、创建及学校详情/更新路径保持 `/api/v1/schools` 和 `/api/v1/schools/{school}`。目录及普通成员输出只含展示字段，不暴露学校配置或资产 ID。浏览器写操作仍校验 Origin 和 CSRF，凭据不进入图片 URL。

代码验证使用 `make check-web`、`make check-miniapp`、`devbox run -- make check-backend`，数据库测试只使用显式隔离连接或 `tools/test_database.py` 创建的临时实例。微信开发者工具及真机需另外验收图片文件展示和账号切换；研发检查不进入业务运行门禁。
