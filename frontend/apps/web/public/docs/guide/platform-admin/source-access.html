WeKeeper 来源接入

部署人员在后端配置 LINJIAN_WEKEEPER_ORIGIN、LINJIAN_WEKEEPER_KEY_ID、LINJIAN_WEKEEPER_SECRET。一个下游对应一条调用方凭据；secret 直接用于请求签名，不在数据库保存，不需要 LINJIAN_SOURCE_MASTER_KEY_V1。

“WeKeeper 连接”只显示配置和验证状态，验证全局配置后，在“学校消息路由”只填写 WeKeeper 分配给本校的 route_id 和启停状态，无需连接 ID。页面不提供凭据录入或密钥回显。每所学校只维护一条路由配置；一个 Linjian 实例只对应一个全局 WeKeeper，各校使用独立 route_id，不选择连接。保存更新本校原记录，停用仍保留该配置；历史消息使用原有冻结路由。一个路由只绑定一所学校，WeKeeper 不保存学校目录。

修改后端配置并重建 API 容器后生效。已有连接的内部归属和历史消息保持不变，不会给历史事件使用另一 origin 或 key_id 的凭据。

来源发件记录显示路由、收件状态、阻塞原因和发送摘要。收件与素材更新不代表已经发群。修复凭据或授权后可重试同一事件，不生成新 ID；存量 v1 不会自动转换成 v2，需按迁移安排处理。

请求均由 Linjian 主动发起。WeKeeper 不回调 Linjian，不查询其在线状态，也无需配置下游可信网址。内容链接只用于消息展示。
